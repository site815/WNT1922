# Interface module

This folder provides the campaign interface for the native Unreal game. `index.html` is the CEF entry page; `app.mjs` coordinates screens, and the CSS files provide the shared panel, battle, title-screen and compact-header layouts. Unreal renders terrain, water, sky, ships and lighting beneath the transparent interface. The removed Three.js globe and voxel renderer are not runtime dependencies. Opening the page outside Unreal shows native-launch guidance instead of a browser graphics fallback.

The UI sends serializable commands through `simulation-client.mjs`. It displays worker snapshots and read-only mechanics queries; it must not alter resources, inventories or simulation time itself. There is no arbitrary state-edit callback across the worker boundary. Screen animation and camera movement are separate from simulation ticks.

`unreal-scene.mjs` owns the transparent input surface and native bridge, while `unreal-scene-packet.mjs` serializes visible scene records. Neither creates a WebGL context. The native controller owns camera movement and actual mesh picking; selection and hover results return through the bridge. Enemy contacts come from observed intelligence, not hidden enemy state. Scene bounds follow the visible map aperture when panels or the opening screen scroll.

The world is a north-up Equal Earth terrain surface with continuous horizontal wrapping and longitude/latitude lines. Geography reprojects around the current central meridian while panning. Wheel input zooms from strategic overview to ship detail; right-drag pans, left-click selects and left-drag selects owned fleets. Middle-drag orbit is available at close ship range; any outward zoom restores north-up overhead viewing. Battles and the gallery allow orbiting independently. Home returns to the overview; Page Up and Page Down zoom. The lower map legend shows current zoom without a separate atlas control bar.

The native game opens in a decorated 1800×1000 window and preserves that minimum client area. Resizing and maximizing are supported; fullscreen is disabled. A smaller display cannot show the entire minimum window plus its frame. The HTML interface does not override this native window policy.

`fleet-formation.mjs` places stable metre-based ship stations around each fleet's authoritative campaign position. Surviving ships retain their stations when another hull is lost. Fleet anchors are not moved to convenient water or combined with unrelated fleets. These are representative formations: the campaign does not record individual tactical tracks or exact harbor berths.

`merchant-scene.mjs` expands the player's active convoys into one presentation identity per surviving merchant hull, with the same formation rules. It does not expose enemy convoys or expand idle national merchant capacity. Native distance and visibility management determine which detailed meshes are loaded and shown. The stored Hog Island Type A model represents civilian cargo vessels. Merchant GRT remains an aggregate registered-volume measure; the artwork does not invent per-ship economic statistics. Selecting a merchant opens its convoy information and hull display index.

Detailed ship assets are self-contained GLBs under `assets/models/ships`, loaded directly by Unreal through the pinned glTFRuntime plugin. The current registry has 198 detailed models, all 281 campaign/class mappings, named opening-battle fits and 14 original player-design categories. Earlier JSON recognition meshes remain reference data only. Missing named artwork remains an explicit status symbol rather than an unrelated historical ship. Ports still use navigation symbols where scenery is absent. `model-gallery.mjs` exposes native ship inspection and attribution. See [asset coverage and authoring](../assets/models/README.md); model-buffer checks do not establish native visual quality or exact historical reconstruction.

Campaign navigation contains menus01–10. The Battle reports page combines an after-action tab and a 3D viewer tab in the same report window. `battle-chrome.mjs` and its stylesheet share compact campaign-style tiles, sound controls and panel widths with standalone battles. `battle-watch.mjs` presents observed battle frames, recorded losses and shared ship-group condition through the same native renderer. Formation spacing and damage effects illustrate the recorded action. Opening Watch explicitly pauses; live Next sends the protected `battle-next` command for one whole-world 15-minute tick. Recorded navigation never steps the simulation. Closing leaves play paused. `attritionView` shows saved monthly consequences of minor actions. The mechanics rules define decisive qualification and replay retention limits.

`start-screen.mjs` splits the title into Campaign and Tactical Battles. Its preset and custom buttons open the actual isolated tactical session, selecting the requested setup. There is no automatic title demo, native viewport or playback timer. `start-battle-data.mjs` remains only as legacy aggregate-record test data. `tactical-engagements.mjs` offers scripted Historical playback and unforced Free simulation; all historical rules and source notes live in `combatmechanics/`. Campaign encounters never opt into a historical script.

`battle-audio.mjs` follows the native battle packet clock, deduplicating event keys across rolling frames. `sound.mjs` mixes layered offline weapon, impact, splash, aircraft and sinking voices through a dedicated limited battle bus. `battle-synthesis-worker.mjs` prewarms deterministic stereo buffers away from the UI thread. Audio begins only after a user gesture; pausing, hiding, seeking, quick resolution and scene disposal cannot replay stale cues. Report SFX changes persist in the campaign; standalone battle preferences do not change campaign data.

The shell keeps the native world behind ministry tiles. Command, land and strategic-air pages leave it interactive around their panels; covering pages disable background scene input. Top bars and navigation own their input surfaces, while clear chart space passes pointer events through. Dialog bounds follow the workspace below the top bars, and panel close controls return to the Command Map.

`news-ticker.mjs` displays routine bulletins and `news-navigation.mjs` resolves stable report, ship, contact or panel references. Choices and war announcements use `diplomacy-popup.mjs`; deferral, resumption and deadline effects remain in the mechanics worker. Popup positioning keeps navigation and resources accessible.

`diplomatic-offers-view.mjs` shows incoming resource exchanges in Diplomacy and a pending-offer alert beside the ticker. Offers use explicit Yes/No controls, expire after fourteen simulated days without an exchange, and never open a popup or pause on arrival. Both countries' quoted resource changes and current acceptance blockers are visible; the worker owns settlement and expiry.

Current validation and remaining release checks are recorded in [SYSTEMS-CHECK.md](../SYSTEMS-CHECK.md). Historical browser and portable-release evidence there does not certify the current native renderer.

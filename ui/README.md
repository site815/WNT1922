# Interface module

All screen rendering, controls, map motion, hover details, sound/music playback, browser-side save transport and styles live here. `index.html` is the entry page; `app.mjs` coordinates screens. `styles.css` defines the shared interface, with globe, battle, title-screen and compact-header layouts in their corresponding CSS files. The bundled Three.js r180 modules in `vendor/three/` provide offline WebGL2 rendering and retain their license notice.

The UI sends serializable commands through `simulation-client.mjs`. It displays worker snapshots and read-only mechanics queries. It must not alter resources, inventories or simulation time itself. There is no arbitrary state-edit callback across the worker boundary.

Map animation uses animation frames between simulation snapshots. Pausing or scrolling the interface does not move simulation work onto the UI thread.

`world-scene3d.mjs` renders one persistent 3D globe scene with political terrain, geographic grid, routes, contacts and ship meshes. `globe-geometry.mjs` supplies spherical terrain and tangent coordinates; `globe-camera.mjs` owns the perspective camera and continuous zoom. The camera moves from the world overview to ship detail without switching to a separate tactical screen. Selection raycasts the actual geometry. Enemy hulls never come from hidden enemy state; contact markers use the player's observation list.

The globe supports 1–65,536× zoom, with individual ship meshes at 2,048× and fleet or convoy double-click focus at at least 4,096×. Wheel input zooms, left-drag turns the globe, and right-drag or Shift-drag orbits and tilts. Home resets the overview; Page Up and Page Down zoom. The readout lives in the lower map legend, with no separate atlas control bar. Review formations move into clear water when necessary and use leaders to retain their real strategic locations. These display offsets never change simulation positions.

`voxel-models.mjs` loads the 181 editable ship JSON files directly. `three-vessels.mjs` turns every cuboid into shared, cached 3D geometry with normals and vertex colors; source X stays X, source height becomes Y-up, and source beam becomes Z. Standard materials respond to scene lighting. World and battle scenes use these same model meshes. Geometry can be disposed explicitly when reloading the collection. The earlier `isometric-scene.mjs` and `voxel-renderer.mjs` remain legacy drawing code, not the production globe or battle renderer; pure formation helpers in `isometric-math.mjs` are still shared.

`merchant-scene.mjs` expands only the player's active convoys into one visible freighter per surviving hull, using stable display identities and the same deterministic formation spacing as naval ships. It has no artificial hull cap, does not expose enemy convoys, and does not expand idle national merchant capacity. The generic freighter is an original model stored in `assets/voxels/ships/generic/merchant-freighter.json`. Merchant GRT is an aggregate registered-volume measure; a model does not invent per-ship crew, armament or dimensions for the economy. Clicking a merchant opens its convoy information with the selected hull's display index.

`battle-watch.mjs` displays the worker's observed battle frames, recorded losses and shared ship-group condition, and exports the real 3D viewer from `battle-scene3d.mjs`. The viewer uses a perspective camera, sea plane and raycastable ship meshes; scroll zooms, left-drag pans, and right-drag or Shift-drag orbits. Formation offsets, approach spacing and damage impacts are illustrative. Opening Watch explicitly pauses; live Next sends the protected `battle-next` command for one whole-world 15-minute tick. Recorded navigation never sends a simulation step. Closing leaves play paused. `attritionView` shows the saved monthly consequences of minor actions. The mechanics rules file defines decisive qualification and replay retention limits.

`start-screen.mjs` keeps campaign and navy choices compact. `start-battle-demo.mjs` cycles the same 3D battle viewer through scripted historical demonstrations from `start-battle-data.mjs`, with visible illustration/model limits and official historical source links. The demo owns no campaign or save state. Its preserved host retains playback while selecting a navy, and its timers/rendering suspend for hidden windows, reduced motion and modal dialogs, then stop on campaign entry.

The shell keeps one globe mounted behind the ministry tiles. Command, land and strategic-air pages leave it interactive around their right-hand panel; other pages cover it with a scrolling content tile and disable background globe input. Top bars and navigation retain their own input surfaces, while only empty chart space passes pointer events through. Dialog bounds follow the clear workspace below the top bars.

`news-ticker.mjs` displays each routine bulletin once and `news-navigation.mjs` resolves its stable report, ship, contact or panel reference. Choices and war announcements use `diplomacy-popup.mjs`; deferral, resumption and deadline effects remain in the mechanics worker. Popup positioning follows the workspace bounds so navigation and resources remain visible.

`diplomatic-offers-view.mjs` shows incoming resource exchanges in Diplomacy and keeps a pending-offer alert beside the ticker. Offers use explicit Yes/No controls, expire after fourteen simulated days with no exchange, and never open a popup or pause on arrival. Both countries' quoted resource changes and current acceptance blockers are visible; the worker owns all settlement and expiry.

For reuse, copy this folder as the presentation layer and adapt the catalog, read-model and command interfaces. Game-specific naval screen layouts are intentionally retained; this is not a separate UI framework or package build.
